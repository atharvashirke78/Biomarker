What is this pipeline?


An automated RNA-seq workflow. You give it paired-end FASTQ files from two groups (for example tumour and normal tissue) plus a small table saying which sample belongs to which group. In one run it checks the input, measures gene expression, finds the genes that differ between the groups, applies pre-set rules to keep only robust candidate biomarker genes, and, when there are enough samples, builds a small gene score with a cutoff. Everything ends in one report.


What is it used for?


  • discoveryGenerating hypotheses about diagnostic biomarker genes in a development cohort (tumour vs normal, case vs control).
    • 

  • standardisedProcessing RNA-seq cohorts the same way every time (same tools, versions, thresholds and seeds), with a manifest of what ran.
    • 

  • QCScreening RNA-seq samples: mapping rates, read quality, outliers, and failed samples are flagged automatically.
    • 

  • explorationA quick overview of differential expression and pathways for a new cohort.
    • 

  • teachingShowing how a full RNA-seq analysis fits together, step by step (the demo above).


Typical use cases


  • A lab has FASTQ files from 10–60 tumour and normal samples and wants QC, differential expression and a first candidate gene list.
    • 

  • A team re-analyses a public cohort with a fixed, documented workflow.
    • 

  • A group checks whether a small cohort is large enough for the full model, and gets a clear message if it is not.


What you get


  • A sample QC table (PASS / WARN / FAIL), counts, and cohort QC plots.
  • Differential-expression tables, volcano / MA / heatmap, and pathway enrichment (ORA and GSEA).
    • 

  • A candidate table showing which rules each gene passed, and, when feasible, a model: a small gene panel, its score formula and cutoff, with performance measured on the same samples.
    • 

  • One HTML report with the methods used, QC findings and limitations.


How the steps fit together


Each sample is processed on its own (verify, trim, align, count, quantify, QC) and these steps run in parallel as far as memory allows. When all samples are done, the group-level steps run on all samples together (merge, cohort QC, differential expression, pathways, candidate rules, model, report). The live view shows each step and what it does.


Limitations — please read


  • Research use only. It is not a diagnostic device, and nothing it produces is clinically validated.
    • 

  • Candidate genes are hypotheses. They need independent validation on samples that were not used to find them. The performance shown for the model is computed on the same samples that chose the genes and the cutoff, so it is optimistic.
    • 

  • Input limits: human samples only (GRCh38, GENCODE v50); paired-end bulk RNA-seq; exactly two groups; at least 3 samples per group; one pair of files per sample (merge lanes first).
    • 

  • Sample size: the robustness rule needs at least 10 leave-one-out refits, so with fewer than 10 samples no gene panel is produced (the run still gives QC, counts, differential expression and pathways). Above 60 samples the current leave-one-out method is not allowed. A small cohort gives weak and unstable results.
    • 

  • Stability: the gene selection can change with the order of the candidates and the random seed. The Salmon route is not exactly repeatable run to run for some samples.
    • 

  • Design: one batch factor is adjusted for; paired tumour/normal samples from the same patient are not modelled as pairs; no covariates such as age or sex.
    • 

  • Prognostic and predictive analyses (survival, treatment response) are not implemented.
    • 

  • Time and capacity: about 3 hours for 19 full-size samples on 16 CPUs and 64 GB; one job at a time on this pod.
    • 

  • This prototype has no login: it only listens on this machine. Commercial, licensing and regulatory questions have not been cleared.


Not for


Diagnosing patients or any clinical decision; other species; single-end, long-read or single-cell data; more than two groups.


Status


The standardised version of the scripts is being validated against an earlier successful 19-sample run. The demo uses real data but is a tool demonstration only.
